# Mission: Technical Writing Engineering Fundamentals

## Why

Build the engineering and analytical judgment needed to move from maintaining Milvus-related documentation to competing for senior developer-documentation and documentation-architecture roles. The outcome is a public portfolio that the learner can explain and defend, not merely a site that an assistant built.

## Success looks like

- Design a layered documentation system and defend separate choices for the portal, REST/OpenAPI reference, language-native SDK reference pipelines, and governance.
- Trace REST and Python, Java, Go, and Node.js SDK reference content to its technical source; use the mature Python reference as a comparison baseline, not as the only SDK.
- Set up and explain a small docs-as-code quality workflow, then present the work as a credible case study.

## Constraints

- Eight-week learning sprint with at least eight hours per week.
- Public, independent project using synthetic vector-search examples; no proprietary Milvus or employer material.
- Each capability follows explain → learner practice → review → evidence; completed implementation alone is not evidence of learning.

## Out of scope

- Practising several documentation portals or four SDK generators in depth.
- Rebuilding a database or production SDK.
- Treating assistant-generated implementation as learner mastery.
