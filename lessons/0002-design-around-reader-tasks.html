Lesson 2 · Documentation Architecture

先识别读者此刻要做什么

同一个“consistency level”主题，可能需要教程、How-to、Reference 和 Explanation 四种内容。信息架构的起点不是给页面贴标签，而是识别读者所处的情境、目标和此刻需要的帮助。

建议用时 35–45 分钟 前置：已完成 Lesson 1 产出：最小信息架构假设
这节课的一个胜利

完成后，你能把“Python 开发者”这种宽泛受众，改写成可设计内容的读者任务，并能解释为什么 Diátaxis 类型不应被机械地复制成四个空目录。

角色还不是需求

“Python 开发者”只说明了读者的一部分背景。同一个人会在不同时间提出完全不同的问题：

读者此刻的情境真正的问题需要的帮助
第一次接触向量数据库“你能带我成功跑通一次检索吗？”受控、可成功的学习路径
正在给已有应用增加一致性设置“我应该怎样完成这项修改？”面向目标的操作步骤
代码写到一半，忘了默认值“这个参数的准确取值是什么？”可快速查询的技术事实
正在评估延迟与一致性的取舍“为什么会有这些级别，影响是什么？”背景、联系和设计原理
把受众改写成任务

使用这个最小句式：当……时，我想……，以便……。情境限制内容入口，目标决定页面的工作，结果帮助你判断这项内容是否真的解决了问题。

用两个问题定位内容形态

Diátaxis 不是四个孤立标签，而是一张由两个维度组成的地图：

获得能力：读者正在学习应用能力：读者正在工作
需要行动Tutorial
带领读者完成一次可理解、可成功的学习经历		How-to
帮助已有基础的读者完成一个真实目标
需要认知Explanation
帮助读者理解背景、原因、联系和取舍		Reference
准确、完整地描述读者工作时要查询的事实

遇到模糊页面时，不要先看标题里有没有 “guide”。问两个问题：

  1. 读者现在需要采取行动，还是获得认知？
  2. 读者正在获得能力，还是应用已有能力？

同一个主题为什么需要四个页面

以 consistency level 为例。一个名为 “Consistency guide” 的大页面很容易同时承担四种工作，结果是谁都难以快速使用。拆分以后，每一页有一个清晰承诺：

TUTORIAL · 引导学习

完成第一次可检索写入

课程控制数据、步骤和结果；只使用一个预先选好的级别，确保初学者成功。

HOW-TO · 解决任务

为查询配置一致性级别

假设读者已有 collection 和客户端，直接帮助其完成配置目标。

REFERENCE · 查询事实

consistencyLevel 参数

列出类型、允许值、默认值、错误、版本，以及 REST 与 SDK 的语言表达。

EXPLANATION · 理解原理

一致性、延迟与可见性

解释为什么存在不同级别、它们之间的联系，以及选择时承担的取舍。

这里不是要求四页必须等长

有些主题暂时只需要 Reference 和一个 How-to。Diátaxis 官方也明确提醒：不要先创建四个空结构，再强迫内容填进去。它首先是判断用户需要和修正内容的工具。

练习 A：按读者需要分类

判断下面六个页面此刻主要帮助读者做什么。四个答案都使用四个汉字，避免视觉长度提示。

Diátaxis 不是导航菜单生成器

直接建立 “Tutorials / How-to / Reference / Explanation” 四个顶级目录，看起来很整齐，却可能要求读者先理解我们的内容模型，才能找到自己的任务。更稳妥的顺序是：

  1. 列出重要的读者情境和 top tasks；
  2. 判断每项任务需要哪一种内容形态；
  3. 用读者能识别的语言形成入口和分组；
  4. 检查相邻内容能否在读者需要改变时互相连接；
  5. 再用搜索、支持问题或任务测试验证这套假设。

因此，一个初始门户可以使用 “Get started / Build applications / API & SDK Reference / Concepts” 作为入口假设，但它不是因为四个名称分别对应 Diátaxis 四象限才正确。它必须能够解释：哪些重要任务从哪个入口开始，以及读者如何转向相邻内容。

练习 B：提交你的最小信息架构假设

下面不是让你写完整 IA 文档。请根据你维护 Milvus 文档的经验，在聊天里补完四行。我会重点检查“任务是否具体”以及“入口是否使用读者语言”。

1. 一个重要读者情境：当……时，读者想……，以便…… 2. 这项需要主要属于：Tutorial / How-to / Reference / Explanation，因为…… 3. 我会让读者从“……”这个入口开始，而不是从“……”开始，因为…… 4. 完成或读完后，最需要链接到的相邻内容是……，因为……
提交前检查
  • 情境中包含触发条件，而不只是“某类开发者”。
  • 目标描述读者要完成或理解什么，而不是“阅读文档”。
  • 内容类型由读者当下的行动/认知与学习/工作状态决定。
  • 入口名称是读者可识别的任务或对象，不是内部团队名称。
  • 相邻链接服务于读者需求的变化，而不是为了增加链接数量。
本节主来源

先阅读官方的 Diátaxis in five minutes 和 Diátaxis compass。特别注意官方的 应用建议：不要把四个分类机械地变成空目录。随时可查看内容架构速查。

完成标准

练习 A 用于即时校准；真正通过需要你提交练习 B，并能说明为什么同一个主题可能需要不同页面，以及为什么内容类型不能自动替你决定导航。

如果你对 Tutorial 和 How-to、Reference 和 Explanation 的边界不确定，直接把具体页面或场景告诉我。边界问题本身就是这节课最有价值的材料。
