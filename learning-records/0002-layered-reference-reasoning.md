# Reasoned across layered reference surfaces

The learner can separate portal, REST contract, SDK source, and governance responsibilities; when REST and Python defaults disagree, they now classify the symptom as cross-surface drift, verify contracts, code, tests, and behavior, and only then assign a root cause. They also distinguished Python feature-coverage maturity from docstring and generation-pipeline maturity, which changes the Python exercise from “copy the mature system” to “build a small pipeline, then test it against one or two public PyMilvus methods.”

## Evidence

The learner explained Docusaurus as a unified reader entrance rather than an API fact owner, traced OpenAPI through rendering and publication, corrected an initial implementation-first diagnosis of a REST/Python default mismatch, and approved a staged synthetic-to-real SDK Reference experiment.

## Implications

Lesson 5 should teach a complete synthetic docstring-to-Reference pipeline before introducing PyMilvus dependency and source-verification complexity. Lesson 1 still requires the learner to revise the ADR before portfolio evidence is complete.
