# Reasoned across layered reference surfaces

The learner can separate portal, REST contract, SDK source, and governance responsibilities; when REST and Python defaults disagree, they now classify the symptom as cross-surface drift, verify contracts, code, tests, and behavior, and only then assign a root cause. They also distinguished Python feature-coverage maturity from docstring and generation-pipeline maturity, which changes the Python exercise from “copy the mature system” to “build a small pipeline, then test it against one or two public PyMilvus methods.”

## Evidence

The learner explained Docusaurus as a unified reader entrance rather than an API fact owner, traced OpenAPI through rendering and publication, corrected an initial implementation-first diagnosis of a REST/Python default mismatch, and approved a staged minimal-example-to-real-source SDK Reference experiment. On 2026-08-31, the learner reviewed and accepted ADR 0001 after its decision question, constraints, same-layer comparisons, trade-offs, validation gates, and reversal conditions were made explicit.

## Implications

Lesson 5 should teach a complete docstring-to-Reference pipeline with a course-built minimal Python SDK example before introducing PyMilvus dependency and source-verification complexity. For Lesson 1, the assistant may structure the decisions as an ADR draft; portfolio evidence comes from the learner's review and ability to defend or correct it, not from manually editing unfamiliar Markdown.
