四种内容的写作约束

类型页面承诺应该包含最常见的越界
Tutorial让学习者获得一次安全、可理解的成功受控步骤、可验证结果、最少必要解释加入太多选项、背景和生产配置
How-to帮助已有基础的读者完成一个真实目标前置条件、目标步骤、分支与验证从零教学，或罗列所有参数
Reference准确、完整、一致地描述产品事实签名、类型、默认值、允许值、错误、版本混入长篇原理和任务流程
Explanation建立原因、机制、联系和取舍的理解背景、为什么、比较、影响和边界伪装成步骤，或复制参数表

从任务到导航的五步算法

  1. 收集情境：记录触发事件、已有知识、目标和限制。
  2. 写 top task：使用读者动词，例如“完成检索”“迁移接口”“核对默认值”。
  3. 选内容形态：用行动/认知与获得/应用能力定位主要模式。
  4. 提出入口：用读者能识别的任务、旅程或产品对象命名，不暴露内部组织结构。
  5. 验证路径：检查关键任务能否被发现、完成，以及读者需求变化时能否自然转向相邻内容。
重要边界

Diátaxis 帮助判断一份内容正在承担什么工作，但不会自动生成站点导航。不要先建立四个空目录；让结构从真实任务和逐步改进中形成。

最小 IA brief

读者情境：当……时…… Top task：读者要…… 内容形态：Tutorial / How-to / Reference / Explanation 建议入口：…… 页面承诺：完成后，读者能够…… 相邻链接：…… 验证方式：我会观察/检查……

快速诊断

  • 如果页面不断解释“为什么”，但读者正急着完成任务，把解释移出 How-to 并建立链接。
  • 如果 Reference 按用户旅程排列而找不到产品对象，检查它是否应该更贴近 API、模块或类型结构。
  • 如果 Tutorial 要求读者自己选择大量配置，缩小自由度并由作者负责成功。
  • 如果导航标签只有内部团队能理解，改用读者任务、产品对象或成熟旅程语言。
