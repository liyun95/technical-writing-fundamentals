统一入口 ≠ 统一事实来源

一个门户可以让所有 Reference 看起来属于同一产品，但 REST、Python、Java、Go 和 Node.js 仍应保留各自可追溯的技术源与生成边界。

比较语义，不比较拼写

同一个能力在不同语言中不一定同名或同形。Python 可能使用 consistency_level，Java 或 Node.js 可能采用 consistencyLevel，Go 可能把它放进 options struct。需要核对的是：

  • 这个能力是否存在，适用于哪些操作；
  • 类型、允许值、默认值和是否必填是否一致；
  • 错误、弃用状态、版本可用性和示例行为是否一致；
  • 语言惯用法造成的差异是否被明确记录。

漂移排查算法

  1. 命名变更概念：先写“新增一致性级别选择”，不要从某个语言的参数拼写开始。
  2. 列出公开 surface：REST、Python、Java、Go、Node.js；标明不支持、未发布或待验证，避免默认全部同步。
  3. 回到各自事实源：核对签名、类型、默认值、允许值、错误和版本。
  4. 比较语义：区分真实能力差异与语言惯用表达差异。
  5. 检查读者输出：确认生成页面、导航、搜索和版本标签展示的是预期版本。
  6. 自动化稳定规则：优先自动检查可机器判定的 surface 存在性、类型或枚举；把行为解释保留给人工评审。
